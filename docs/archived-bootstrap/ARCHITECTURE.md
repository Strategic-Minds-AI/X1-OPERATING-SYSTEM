## Critical boundaries
- **Vision Cortex:** determines purpose, evaluates strategy and runs Council recommendations. It **does not** bypass the X1 queue or sign production releases.
- **Council:** peers contribute separately sourced reviews. One model role-playing nine people is a simulation and cannot qualify as an independent nine-member vote. Security veto blocks recommendation; operator approval required for protected actions regardless of majority.
- **GPT/Eden:** interfaces that produce draft work packets. Authenticated server validates tenant ownership, consent and signed immutable plan.
- **X1:** one authoritative queue/lease/idempotency ledger. Check existing worker and primary heartbeat before any new scheduling.
- **JARVIS/Railway:** worker runtimes, sandbox isolation, budget and signed audit receipts. Current local synthetic builder only generates a packet. Real code-writing/preview must be independently demonstrated.
- **OpenClaw:** optional isolated agent adapter after code sandbox proof; not a second default orchestrator. One shared OpenClaw Gateway is not tenant isolation.
- **Cloud Browser / Fault Line:** read-only research with client business consent and independent testing; no covert personal skip tracing or private account scraping.
- **Vercel/Supabase/GitHub:** existing frontend/app/API and data/source providers with approved access only. Production secrets server side.
- **Original Base44:** preserve functional original; extract modules one by one with behavior parity. No Base44 SDK/credits required in target.
- **Client portal:** shared product modules but tenant-owned data and roles platform_admin, tenant_owner, editor, viewer, backed by verified RLS and negative cross-tenant tests.

## Delivery promise
1–2 sentence client request -> guided discovery when requirements missing -> scoped quote -> approval -> genuine sandbox app/website -> verified preview -> client approval -> operator-controlled release. No unreviewed instant production and no thin doorway-page multiplication.
